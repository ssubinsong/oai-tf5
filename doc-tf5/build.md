## CMake Option

In `CMakeLists.txt`:

```cmake
option(TF5_ENABLE_TESLA
       "Enable TESLA broadcast authentication for SIB1 (fake base station protection)"
       OFF)

if(TF5_ENABLE_TESLA)
  add_definitions(-DTF5_ENABLE_TESLA)
endif()
```

---

## Build Commands

**Build gNB and UE with TESLA enabled**:
```bash
cd cmake_targets
./build_oai --ninja --gNB --nrUE -w SIMU --cmake-opt -DTF5_ENABLE_TESLA=ON
```

**Build gNB only**:
```bash
./build_oai --ninja --gNB -w SIMU --cmake-opt -DTF5_ENABLE_TESLA=ON
```

## Key Management

### Generate TESLA Keys

Before running gNB and UE with TESLA enabled, generate the Ed25519 key pair and certificate:

```bash
./scripts/tf5_generate_cert.sh
```

This creates the following files in `./tesla_keys/`:
- `gnb_tesla_privkey.pem` - Ed25519 private key (gNB only)
- `gnb_tesla_cert.pem` - Self-signed certificate containing public key (gNB and UE)

### Default Paths

The default paths are configured so that keys generated by the script are automatically used:

| Component | Parameter | Default Path |
|-----------|-----------|--------------|
| gNB | `--tesla-privkey` | `./tesla_keys/gnb_tesla_privkey.pem` |
| gNB | `--tesla-cert` | `./tesla_keys/gnb_tesla_cert.pem` |
| UE | `--tesla-gnb-cert` | `./tesla_keys/gnb_tesla_cert.pem` |

### Running with TESLA

After generating keys, run gNB and UE normally:

```bash
# gNB (uses default paths)
./nr-softmodem -O gnb.conf

# UE (uses default path)
./nr-uesoftmodem -O ue.conf
```

### Custom Paths

Override the default paths with command-line parameters:

```bash
# gNB with custom paths
./nr-softmodem -O gnb.conf \
    --tesla-privkey /path/to/privkey.pem \
    --tesla-cert /path/to/cert.pem

# UE with custom path
./nr-uesoftmodem -O ue.conf \
    --tesla-gnb-cert /path/to/cert.pem
```

## Dependencies

| Dependency | Purpose |
|------------|---------|
| OpenSSL | HMAC-SHA256, Ed25519, X.509 certificates |
| herumi/bls | Ed25519 signatures |

The herumi/bls library is included as a submodule at `cmake_targets/bls/`.
