## CMake Option

In `CMakeLists.txt`:

```cmake
option(TF5_ENABLE_TESLA
       "Enable TESLA broadcast authentication for SIB1 (fake base station protection)"
       OFF)

if(TF5_ENABLE_TESLA)
  add_definitions(-DTF5_ENABLE_TESLA)
endif()
```

## Build Commands

**Build gNB and UE with TESLA enabled**:
```bash
cd cmake_targets
./build_oai --ninja --gNB --nrUE -w SIMU --cmake-opt -DTF5_ENABLE_TESLA=ON
```

**Build gNB only**:
```bash
./build_oai --ninja --gNB -w SIMU --cmake-opt -DTF5_ENABLE_TESLA=ON
```

## Key Management

### Generate TESLA Keys

Before running gNB and UE with TESLA enabled, generate the BLS key pair:

```bash
./scripts/tf5_generate_bls_keys.sh
```

This creates the following files in `./tesla_keys/`:
- `gnb_tesla_privkey.bin` - BLS secret key (32 bytes raw binary, gNB only)
- `gnb_tesla_pubkey.bin` - BLS public key (96 bytes raw binary, gNB and UE)

The key generation utility (`tf5_bls_keygen`) is automatically built when TESLA is enabled.

### Key File Format

Keys are stored as raw binary files (no PEM encoding):

| Key Type | Size | Description |
|----------|------|-------------|
| Secret key | 32 bytes | Fr element (scalar field) |
| Public key | 96 bytes | G2 point (compressed) |

Inspect generated keys with:
```bash
xxd tesla_keys/gnb_tesla_privkey.bin  # Should show 32 bytes
xxd tesla_keys/gnb_tesla_pubkey.bin   # Should show 96 bytes
```

### Default Paths

The default paths are configured so that keys generated by the script are automatically used:

| Component | Parameter | Default Path |
|-----------|-----------|--------------|
| gNB | `--tesla-privkey` | `./tesla_keys/gnb_tesla_privkey.bin` |
| gNB | `--tesla-pubkey` | `./tesla_keys/gnb_tesla_pubkey.bin` |
| UE | `--tesla-gnb-pubkey` | `./tesla_keys/gnb_tesla_pubkey.bin` |

### Running with TESLA

Following standard OAI conventions, run from the **build directory**:

```bash
cd cmake_targets/ran_build/build
```

**Option 1: Generate keys in build directory**

```bash
# Generate keys relative to current directory
../../../scripts/tf5_generate_bls_keys.sh
# Creates ./tesla_keys/ in build directory

# Run gNB (RF simulator mode)
sudo ./nr-softmodem \
    -O ../../../targets/PROJECTS/GENERIC-NR-5GC/CONF/gnb.sa.band78.fr1.106PRB.usrpb210.conf \
    --rfsim --gNBs.[0].min_rxtxtime 6

# Run UE (in another terminal, from same directory)
sudo ./nr-uesoftmodem -r 106 --numerology 1 --band 78 -C 3619200000 --rfsim \
    -O ../../../targets/PROJECTS/GENERIC-NR-5GC/CONF/ue.conf
```

**Option 2: Specify absolute key paths**

If keys were generated elsewhere (e.g., project root):

```bash
# Run gNB with explicit key paths
sudo ./nr-softmodem \
    -O ../../../targets/PROJECTS/GENERIC-NR-5GC/CONF/gnb.sa.band78.fr1.106PRB.usrpb210.conf \
    --rfsim --gNBs.[0].min_rxtxtime 6 \
    --tesla-privkey /path/to/oai-tf5/tesla_keys/gnb_tesla_privkey.bin \
    --tesla-pubkey /path/to/oai-tf5/tesla_keys/gnb_tesla_pubkey.bin

# Run UE with explicit key path
sudo ./nr-uesoftmodem -r 106 --numerology 1 --band 78 -C 3619200000 --rfsim \
    -O ../../../targets/PROJECTS/GENERIC-NR-5GC/CONF/ue.conf \
    --tesla-gnb-pubkey /path/to/oai-tf5/tesla_keys/gnb_tesla_pubkey.bin
```

## Dependencies

| Dependency | Purpose |
|------------|---------|
| OpenSSL | HMAC-SHA256 for key chain and MAC computation |
| blst | BLS12-381 signatures (pk-in-G2 mode) |

The blst library (Supranational) is included as a submodule at `cmake_targets/third_party/blst/`.

### Key Migration Note

**IMPORTANT**: If upgrading from a previous version that used herumi-bls, existing keys
must be regenerated. The blst implementation uses big-endian scalar serialization,
which is incompatible with herumi-bls's little-endian format.

Run `./scripts/tf5_generate_bls_keys.sh` to generate new keys after upgrading.
